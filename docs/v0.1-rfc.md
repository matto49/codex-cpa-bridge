# codex-cpa-bridge v0.1 RFC

## Scope

`codex-cpa-bridge` owns only the Codex-to-CPA bridge layer.

CPA is a black-box Responses-compatible endpoint. The bridge must not inspect, configure, or manage CPA internals,
including TraeX bridge, upstream OAuth, account pools, model routing, retries, tunnels, or quota policy.

## Resource Model

- `official profile`: the normal Codex home, usually `~/.codex`. It is read-only for this tool.
- `cpa profile`: a separate `CODEX_HOME` managed by this tool.
- `cpa endpoint`: a local HTTP base URL such as `http://127.0.0.1:8317/v1`.
- `ssh endpoint`: a loopback-only OpenSSH daemon that forces connections into the CPA Codex wrapper.
- `runtime state`: bridge-owned files under `~/.codex-cpa-bridge`.

## Invariants

- Never write the official profile.
- Never copy or link `auth.json`, sessions, SQLite stores, or cookies between profiles.
- Never write CPA tokens into manifest, config, argv, logs, or generated files.
- Generated files include `managed-by: codex-cpa-bridge`.
- Existing unmanaged files are not overwritten unless `--force` is explicit.
- CPA health checks are black-box only: `/models` and optionally a minimal `/responses` call.

## Commands

- `setup`: configure the isolated profile and sshd, start it, and verify the authenticated loopback SSH entrypoint.
- `models list`: expose the configured model catalog for CLI and UI use.
- `models set`: change one model's `visibility` between `list` and `hide`, preserving other catalog fields.
- `render`: print the isolated CPA `config.toml`.
- `render --write`: atomically write the CPA profile config.
- `adopt`: inspect current state and print an editable manifest suggestion.
- `doctor`: layered human-readable diagnostics.
- `doctor --json`: machine-readable diagnostics for UI or automation.
- `templates`: print wrapper, sshd, launchd, and systemd templates.
- `install`: dry-run bridge-owned file installation.
- `install --write`: write bridge-owned files into `runtime.state_dir`.
- `up` / `down`: start or stop the loopback sshd directly for local testing.

## Current Verification

On devbox, the v0.1 implementation has verified:

- CPA profile config renders and writes to `/data00/home/wangyang.49/.codex-cpa/config.toml`.
- Official `/data00/home/wangyang.49/.codex/config.toml` timestamp did not change during CPA render.
- CPA `/v1/models` is reachable with the configured auth command.
- Loopback sshd can start on `127.0.0.1:2222`.
- A devbox overlay with user `wangyang.49` validates SSH probe and returns the CPA `CODEX_HOME`.
- Unit tests cover profile isolation, dry-run behavior, generated state files, and unmanaged-file protection.

## Current Findings

- Mac/Desktop overlays should set `profiles.official.enforce_native_login = true` because the official profile carries
  the user's native ChatGPT login state. Devbox/headless overlays may set it to `false` when the default Codex provider
  is intentionally CPA.
- The default `bridge.toml` uses Mac user `bytedance`, which is correct for Mac but invalid on devbox. Use
  `examples/devbox.toml` for devbox validation and `examples/mac.toml` for the Mac overlay.
